# TAYA-STEPS

TAYA-STEPS means TAYA Support Translation, Economic Planning and Scenarios. It is a client-side research and policy decision-support prototype for translating youth and parent preferences for early anxiety support into illustrative uptake, reach, service capacity, resource cost, budget impact, equity and exploratory economic scenarios.

**Prototype status:** Literature-informed preference coefficients and selected economic and implementation parameters are illustrative. They are not empirical findings from the TAYA study and must not be used for individual clinical decisions. TAYA-STEPS is not an Australian Government service.

## Streamlined prototype interface

Version 1.0 keeps the full modelling architecture but presents a smaller core workflow for policy reviewers and research stakeholders:

1. **Overview** shows family-compatible uptake, expected starters, annual service cost and workforce required.
2. **Build scenario** exposes the seven service-design choices and two planning-population inputs first. Advanced assumptions are collapsed by default.
3. **Results** groups outputs into Overview, Uptake & reach, Cost & capacity, Equity and Advanced.
4. **Compare** focuses first on the main planning trade-offs across saved scenarios.
5. **Assumptions** explains the evidence grades before exposing technical filters and parameter management.

The optimiser, detailed reports, methods, accessibility and privacy pages remain available as supporting or advanced functions rather than primary navigation items.

## Model architecture

The preference engine calculates systematic utility separately for adolescents and parents/carers:

`V = ASC + setting + wait coefficient × weeks + delivery + parent involvement + professional support + follow-up + cost coefficient × AUD 10 units + subgroup modifiers`.

Binary uptake uses the logistic function. Multi-option comparison uses a numerically stable softmax. Family-compatible uptake is generated by a transparent prototype decision rule selected by the user.

Downstream engines calculate planning-population flow, service-provider resource cost, MBS reference values, workforce capacity, multi-year budget impact, specified equity modifiers, exploratory economic value, Monte Carlo uncertainty, one-way sensitivity and Pareto optimisation.

## Prototype coefficients and parameter replacement

Prototype preference coefficients are in `src/data/prototypeCoefficients.ts`. Every active modelling input has evidence metadata in `src/data/evidenceRegistry.ts` and is graded:

- A: Official Australian source
- B: Direct peer-reviewed evidence
- C: Literature-informed translation
- D: Prototype assumption

The Evidence page can import a validated parameter JSON file without source-code changes. `public/example-parameter-set.json` is a complete test file using the current prototype coefficient values. Imported parameter sets persist only locally. **Restore prototype parameters** returns to the bundled coefficient set.

Future empirical TAYA coefficients should preserve the same named levels and include coefficient means, standard errors, version, date and source metadata.

## Reports and exports

The Reports page generates:

- executive policy brief PDF;
- service planning PDF;
- full technical PDF;
- methods and assumptions PDF;
- Excel workbook with separate modelling worksheets;
- scenario JSON;
- results CSV;

## External AI behaviour

The Policy Assistant works without an API and answers deterministically from current scenario values and the bundled evidence register. The optional external AI briefing feature generates text locally, displays exactly what would be copied, warns against personal or confidential information, then copies the text and opens the selected provider homepage in a new tab. TAYA-STEPS does not automatically transmit scenario information to an external service.

## Privacy

Core calculations run in the browser. Scenarios and imported parameter sets are stored locally. TAYA-STEPS does not collect participant or patient data, does not enable analytics or advertising, and has no embedded API secrets. See `PRIVACY.md` and the in-app Privacy page.

## PWA and offline use

The Vite PWA plugin creates the manifest and service worker, caches application assets and updates versioned caches. After a successful first load, core modelling functions work offline. External evidence links and external AI provider sites naturally require a network connection.

## Important interpretation boundary

Preference-based monetary equivalents derived from DCE cost coefficients are kept separate from monetised health benefits. MBS schedule fees are displayed as reimbursement reference values and are not described as economic opportunity costs. Exploratory economic value uses external assumptions and is not a TAYA effectiveness or cost-effectiveness estimate.
